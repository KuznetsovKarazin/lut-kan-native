# Бенчмарк Mega 2560 и ESP32-C3

Датчики пока не нужны: прошивка использует одни и те же синтетические
ADC/температурные данные и восемь экспортированных моделей. Она измеряет
реальные вычисления платы, но не физическую точность датчиков.

Сравниваются физическая модель, Chebyshev-полином, кубический сплайн и KAN-ребро
с 16 коэффициентами сплайна, монотонная равномерная LUT32 в float32/int16/uint8,
а также неравномерная LUT16/int16. Код учитывает нормировку и перевод в °C.
Монотонность задаётся при обучении; готовая таблица не требует дополнительной
проверки при каждом предсказании.

## Запуск на Windows

Установить Python и Git, если их ещё нет. Выполнить в PowerShell:

```powershell
git clone --branch research/sensor-calibration-recovery https://github.com/KuznetsovKarazin/lut-kan-native.git sensor-recovery-hw
cd sensor-recovery-hw
py -m pip install -r experiments/sensor_recovery/mcu/requirements.txt
py -m platformio device list
```

Подключить одну плату USB-кабелем с передачей данных. Ниже заменить COM5 на её
реальный порт из списка. Закрыть другие Serial Monitor для этого порта.

Mega 2560:

```powershell
py -m platformio run -d experiments/sensor_recovery/mcu -e mega2560 -t upload --upload-port COM5
py experiments/sensor_recovery/mcu/capture.py --port COM5 --out runs/mega_run01.json
```

ESP32-C3 SuperMini:

```powershell
py -m platformio run -d experiments/sensor_recovery/mcu -e esp32c3 -t upload --upload-port COM5
py experiments/sensor_recovery/mcu/capture.py --port COM5 --out runs/c3_run01.json
```

После строки `Serial open` Mega обычно перезапускается автоматически. Если
за 5 секунд не появилась строка `SENSOR_BENCH_V1`, один раз нажать RESET.
После начала бенчмарка больше не нажимать RESET: повторный старт внутри лога
будет отклонён как прерванное измерение. Дождаться `END_SENSOR_BENCH`.
Сохранятся исходный `.log` и проверенный `.json`.
Для C3 порт после прошивки может измениться — снова посмотреть `device list`.
Если загрузчик C3 не подключается: удержать BOOT, нажать и отпустить RESET,
затем отпустить BOOT и повторить загрузку. Профиль DevKitM-1 используется как
Arduino/PlatformIO профиль чипа C3; наличие USB CDC и распиновка конкретного
SuperMini должны быть подтверждены фактическим запуском.

Первый запуск загружает компиляторы и Arduino frameworks. Последующие сборки
используют кэш. После каждой платы нужны два независимых запуска с RESET;
дать файлам разные имена, например run01/run02. Не перезаписывать результаты.

## Что сохраняется

- 401 проверка на модель: MAE, RMSE, максимум ошибки относительно синтетической
  температуры; максимум расхождения с host-вычислением, допуск 0,002 °C.
- 10 серий по 2048 вызовов для каждого метода и для служебного baseline.
  Время включает чтение входов, цикл, вызовы и накопление контрольной суммы;
  печать Serial и acquisition ADC находятся вне измеряемого участка.
- `gross_us_per_call` и отдельно оценка после вычитания медианного baseline.
  Малые/отрицательные разности означают, что накладные расходы надо уточнять.
- `UPDATE_COST_ONLY`: стоимость локального SGD-шага с сохранением монотонности.
  Это отдельная демонстрация стоимости, использующая синтетические цели;
  она не доказывает качество обучения и не равна offline-оптимизатору с
  регуляризацией. Изменяется отдельная float32-копия таблицы на стеке (128 B).

У `FREE_MEMORY_ESTIMATE` разный смысл: AVR оценивает зазор heap/stack,
ESP32 сообщает свободный heap. Эти числа нельзя напрямую сравнивать как
одинаковое измерение пиковой памяти. Размер payload также не равен всему SRAM.

## Проверка и статические размеры без плат

```powershell
py experiments/sensor_recovery/mcu/build_audit.py --out runs/build_audit
```

Скрипт собирает отдельные приложения для каждого метода и baseline, затем
полный бенчмарк. В `FOOTPRINT_ONLY` нет Serial и тестовых массивов; ADC-вход
объявлен volatile, вычисление сохраняется в volatile-выход. Разность размеров
с baseline показывает добавленную стоимость этой конкретной сборки. Это не
оценка stack high-water, памяти обучения или энергопотребления.

Последняя сборка каждой платы — полный бенчмарк. Для обычной прошивки всегда
использовать стандартный `platformio.ini`, а не временный footprint-профиль.

Пакеты: atmelavr 5.1.0, espressif32 6.12.0. Точные версии компилятора и Arduino
framework, размеры и SHA256 ELF сохраняются в отчёте сборки. Исходный
экспорт воспроизводится командой `python experiments/sensor_recovery/export_mcu.py`.
